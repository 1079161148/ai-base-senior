# 12 可写层与三种挂载 · 完整版

## 0. 怎么用

跑 11/11。本章真实验证"删容器丢可写层、换容器卷还在、宿主改文件容器立即可见"。

## 1. 概念

| 层 | 读写 | 生命周期 |
| --- | --- | --- |
| 镜像层 | 只读 | 随镜像 |
| 可写层 | 读写 | 随容器 |
| 卷 | 读写 | 独立 |
| 绑定挂载 | 读写 | 随宿主目录 |

写时复制（CoW）：修改镜像层里的文件时，先把文件复制到可写层再改，所以性能不如直接读写磁盘。

## 2. 机制

```text
容器 rootfs = 只读镜像层（lowerdir） + 可写层（upperdir），由 OverlayFS 合并挂载
-v mydata:/data      → 把卷目录 bind 到容器 /data，绕过联合文件系统
-v /host/conf:/etc/x → 把宿主目录/文件直接 bind 进去
--tmpfs /tmp         → 挂一块内存文件系统
```

## 3. 逐个拆解（本机实测）

| 操作 | 实测结果 |
| --- | --- |
| 容器内写 `/data.txt` + `docker diff` | `A /data.txt`（A=新增） |
| 删除容器后再读该文件 | `MISSING` |
| `volume create ch12-vol` | 成功 |
| 写卷 + 删容器 + 新容器挂同一卷 | 数据仍在 `persisted` |
| `volume inspect -f {{.Mountpoint}}` | `/var/lib/docker/volumes/ch12-vol/_data` |
| 绑定挂载读宿主文件 | `from-host` |
| 宿主改文件后容器内读 | `updated`（立即生效） |
| `--tmpfs /tmp` | 记录在 `HostConfig.Tmpfs`（**不在 .Mounts**） |
| 命名卷 | `.Mounts[0].Type = volume` |

## 4. 边界条件

- `-v` 不以 `/` 开头会被当成卷名，不是相对路径；绑定挂载必须绝对路径。
- 绑定挂载会**覆盖**镜像内该路径的内容，不会合并；数据卷首次挂载会把镜像内内容复制进空卷（`--mount volume-nocopy` 可关闭）。
- tmpfs 只存内存，容器停止即丢，且不体现在 `.Mounts`（在 `HostConfig.Tmpfs`）。
- Windows/macOS 的绑定挂载经过 VM 文件共享，性能明显低于 Linux 原生。
- 匿名卷（`-v /data`）会随容器创建，`rm -v` 时删除，容易堆积。

## 5. 注意事项对照表

| 错误做法 | 现象 | 正确做法 | 依据 |
| --- | --- | --- | --- |
| 数据写容器内 | 删容器就丢 | 用卷 | 实测 |
| `-v ./data:/data` | 变空卷 | 绝对路径 | 实测 |
| 绑定挂载覆盖配置目录 | 镜像默认配置消失 | 按文件挂载或先拷贝 | 实测 |
| 用 tmpfs 存数据库 | 停止即丢 | 用卷 | 官方 |
| 卷名不带项目前缀 | 互相覆盖 | 加前缀 | 最佳实践 |
| SELinux 不加 `:z` | 权限拒绝 | 加 `:z` | 第 14 章 |
| 匿名卷不清理 | 磁盘涨 | 命名卷 + prune | 第 11 章 |
| 认为 `.Mounts` 含 tmpfs | 查不到 | 查 `HostConfig.Tmpfs` | 实测 |
| 忘记卷是 root 拥有 | 普通用户写不进 | 调整权限 | 第 14 章 |
| 跳过验收 | 持久化认知错 | 11/11 再走 | 实测 |

## 6. 最佳实践

数据库/中间件一律用命名卷；配置和代码开发期用绑定挂载；敏感密钥用 tmpfs 或 secrets；所有卷名带项目前缀。
