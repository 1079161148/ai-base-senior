# 14 绑定挂载与权限 · 完整版

## 0. 怎么用

跑 9/9。本章真实验证只读挂载、单文件挂载、覆盖行为与卷复制行为的差异。

## 1. 概念

绑定挂载（bind mount）把宿主机的一个目录或文件直接映射到容器路径。它与命名卷最大的区别是**数据归谁管**：绑定挂载归你，命名卷归 Docker。

## 2. 机制

```text
docker run -v /host/path:/container/path[:ro][:z]
  → dockerd 在容器 mount namespace 里做 bind mount
  → 该路径不再走 OverlayFS，直接指向宿主 inode
ro → mount -o ro（内核级只读）
z  → 重设 SELinux 上下文为 container_file_t
```

## 3. 逐个拆解（本机实测）

| 操作 | 实测结果 |
| --- | --- |
| `-v 目录:/data:ro` 读文件 | `read-only` |
| 只读下写文件 | `Read-only file system`（失败） |
| `.Mounts[0].RW` | `false` |
| `.Mounts[0].Type` | `bind` |
| 单文件挂载 `-v conf:/app.conf:ro` | 读到 `host-value` |
| 空目录挂到 nginx html | `ls` 输出为空（原 index.html 被覆盖） |
| 空命名卷挂同一目录 | `50x.html index.html`（复制了镜像内容） |
| 宿主改文件 | 容器内立即读到新内容 |

## 4. 边界条件

- 绑定挂载**不会复制**镜像内原内容，直接遮蔽；空目录挂上去就是空。
- 命名卷首次挂到**非空**镜像目录时会复制内容；`--mount volume-nocopy` 可关闭。
- 单文件挂载时，若宿主编辑器保存方式是"写临时文件再 rename"，容器内仍指向旧 inode，需重启容器。
- `:z` 只在启用 SELinux 的系统上有意义，其它系统忽略。
- Windows/macOS 的绑定挂载经过 VM 文件共享层，IO 性能明显低于 Linux 原生。

## 5. 注意事项对照表

| 错误做法 | 现象 | 正确做法 | 依据 |
| --- | --- | --- | --- |
| 空目录挂静态资源 | 403/404 | 放好文件或用卷 | 实测 |
| 用相对路径 | 变成空卷 | 绝对路径 | 实测 |
| 生产不给 `:ro` | 容器可改配置 | 加 `:ro` | 安全 |
| RHEL 不加 `:z` | Permission denied | 加 `:z` | 官方 |
| 对 `/etc` 用 `:z` | 安全风险 | 别对系统目录用 | 官方 |
| 挂单文件后热更新 | 不生效 | 挂目录 | 实测 |
| 以为绑定挂载会复制 | 原内容消失 | 理解覆盖行为 | 实测 |
| Windows 用反斜杠 | 解析失败 | 正斜杠 | 实测 |
| 容器内以 root 写宿主目录 | 权限错乱 | `--user` 对齐 | 第 10 章 |
| 跳过验收 | 权限问题不熟 | 9/9 再走 | 实测 |

## 6. 最佳实践

配置/静态资源用 `:ro`；代码热更新挂目录不挂文件；SELinux 系统统一加 `:z`；生产尽量用命名卷 + 配置注入。
