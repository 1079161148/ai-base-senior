# 00 认知地图

## 一句话结论

Docker 是把「应用 + 依赖」打包成标准化镜像、在隔离环境里运行的容器引擎。它只解决一件事：**让同一份软件在任何机器上跑出一样的结果**。记住三个词就够：镜像（模板）、容器（运行实例）、仓库（存放镜像的地方）。

## 最小可运行案例

```bash
docker version                  # 客户端和守护进程都在
docker run --rm hello-world     # 拉镜像 → 建容器 → 运行 → 退出 → 删除
```

## 三大核心概念

| 概念 | 是什么 | 类比 |
| --- | --- | --- |
| 镜像 Image | 只读模板，多层叠加 | 安装光盘 / 类 |
| 容器 Container | 镜像的运行实例 | 运行中的程序 / 对象 |
| 仓库 Registry | 存放与分发镜像 | 应用商店 |

## 最容易踩的坑

| 错误认知 | 真相 |
| --- | --- |
| 容器是"迷你虚拟机" | 容器只是被隔离的普通进程，共用宿主机内核 |
| `latest` 是最新版 | `latest` 只是默认标签名，不保证最新 |
| 装了 Docker 就能跑 Windows 容器 | Linux 容器只能跑在 Linux 内核上，Desktop 背后是小 Linux 虚拟机 |
| 容器删除数据还在 | 可写层随容器删除而消失，要用数据卷 |
| Docker 发明了容器 | namespace/cgroups 早已存在，Docker 做的是组合 + 镜像 + 仓库 |
