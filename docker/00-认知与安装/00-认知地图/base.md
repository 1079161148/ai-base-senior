## 0. 怎么用

先跑 10/10 确认环境，再读下面的原理。这一章不写代码，只建立正确直觉——后面 35 章的所有坑，八成源自这里的误解。

## 1. 概念

Docker 是用 Go 写的开源容器引擎，把应用与依赖打包成标准化镜像，在隔离环境中运行。

"码头工人 + 集装箱"的比喻：集装箱统一了货物运输的规格，Docker 统一了软件交付的规格。有了集装箱，谁都不用关心箱子里装什么、船怎么装；有了镜像，谁都不用关心应用用什么语言、依赖哪个版本。

## 2. 来历与澄清

| 时间 | 事件 |
| --- | --- |
| 2013.03 | 在 PyCon 首次亮相并开源，公司从 dotCloud 改名 Docker |
| 2014 | 底层从 LXC 换成自研 Go 库 `libcontainer` |
| 2015 | OCI（开放容器倡议）成立，统一镜像格式与运行时标准 |
| 2017 | 开源部分独立为 Moby 项目 |
| 2022 | K8s 1.24 移除 dockershim，改用 containerd |

**关键澄清：容器技术不是 Docker 发明的。** `chroot`（1979）、FreeBSD Jail、LXC、namespace、cgroups 都早于 Docker。Docker 的历史贡献是三件事的组合：**镜像（分层、可分发）+ 仓库（Docker Hub）+ 极其好用的 CLI**。

## 3. 架构：C/S 调用链

```text
docker CLI  ──REST API──►  dockerd  ──►  containerd  ──►  runc  ──►  Linux 内核
（遥控器）                  （大管家）     （生命周期）    （真正启动）  namespace/cgroups
```

| 组件 | 职责 |
| --- | --- |
| `docker` CLI | 接收命令，通过 `/var/run/docker.sock` 调 API |
| `dockerd` | 镜像、网络、数据卷等高层管理 |
| `containerd` | 容器全生命周期，K8s 后续直接与它打交道 |
| `runc` | 按 OCI 标准向内核申请隔离与资源限制并启动进程 |

## 4. 三大核心概念

| 概念 | 定义 | 关键点 |
| --- | --- | --- |
| 镜像 Image | 只读、分层、不运行的模板 | 一次构建，到处运行 |
| 容器 Container | 镜像的运行实例，顶部多一层可写层 | 一镜像多容器；生命周期=主进程 |
| 仓库 Registry | 存放与分发镜像的服务 | Docker Hub 最大，企业可自建 |

## 5. 容器 vs 虚拟机

| 维度 | 容器 | 虚拟机 |
| --- | --- | --- |
| 隔离对象 | 进程 | 整台硬件 |
| 是否含内核 | 共用宿主机内核 | 每个 VM 一个完整 Guest OS |
| 启动速度 | 秒级 | 几十秒到分钟 |
| 体积 | 几十到几百 MB | 几 GB |
| 资源开销 | 低 | 高 |
| 隔离强度 | 较弱（内核共享） | 强 |

**结论：容器不是"迷你虚拟机"，本质是被 namespace 隔离、被 cgroups 限制资源的普通进程。** Linux 容器只能跑在 Linux 内核上；Windows/macOS 的 Docker Desktop 背后跑着一个小 Linux 虚拟机。

隔离三件套：

| 技术 | 作用 |
| --- | --- |
| namespace | 独立的进程、网络、文件系统视图 |
| cgroups | 限制 CPU、内存等资源 |
| 联合文件系统（OverlayFS） | 多个只读层 + 可写层叠加成完整文件系统 |

## 6. 能做什么

统一环境、快速部署与回滚、应用隔离、微服务拆分、CI/CD 流水线、几十秒拉起 MySQL/Redis 等中间件、AI 模型服务打包与分发。
