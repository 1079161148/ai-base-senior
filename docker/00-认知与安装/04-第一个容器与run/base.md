# 04 第一个容器与 docker run · 完整版

## 0. 怎么用

跑 8/8。本章是本教程第一次真正"跑起来"，后面所有章节都建立在这里的选项上。

## 1. 概念

| 命令 | 等价于 |
| --- | --- |
| `docker run` | `docker create` + `docker start` |
| `docker run --rm` | 运行结束自动 `docker rm` |

## 2. 机制

```text
docker run [选项] 镜像名 [命令]
                │        └─ 覆盖镜像的 CMD（整体替换）
                └─ 决定网络、挂载、端口、环境变量、是否后台
```

前台模式：容器主进程的 stdin/stdout/stderr 接到你的终端。
后台模式（`-d`）：输出进入容器日志，用 `docker logs` 看。

## 3. 选项逐个拆解

| 选项 | 实测结果 | 注意 |
| --- | --- | --- |
| 默认前台 | 输出 `hi` | 主进程结束容器即退出 |
| `-e` | `$NAME` 读到 `docker` | 密码不要用 -e |
| 镜像名后命令 | `cat /etc/alpine-release` → `3.20.10` | 整体覆盖 CMD |
| `--rm` | 退出后容器不存在 | 排障时别加 |
| `-d -p` | HTTP 返回 `Welcome to nginx` | 应用必须监听 0.0.0.0 |
| `-p 127.0.0.1:18080:80` | `docker port` 显示 `127.0.0.1:18080` | 仅本机可访问 |
| 退出码 | `exit 3` → 宿主返回 3 | CI 靠它判失败 |
| `stop` | 状态变为 exited | SIGTERM → 10s → SIGKILL |

## 4. 边界条件

- 镜像名后的命令会**整体替换** CMD，不是追加（追加用 ENTRYPOINT，见第 18 章）。
- `-p` 只对容器端口有效，容器内服务监听地址必须是 `0.0.0.0`。
- 端口映射默认监听 `0.0.0.0`，公网机器上要显式绑 `127.0.0.1` 或配合防火墙。
- `--rm` 与 `-d` 同时用时，容器停止即删除，日志会丢。
- 容器内 `localhost` 指容器自己，不是宿主机。

## 5. 注意事项对照表

| 错误做法 | 现象 | 正确做法 | 依据 |
| --- | --- | --- | --- |
| 服务监听 127.0.0.1 | 端口映射进不去 | 监听 0.0.0.0 | 实测 |
| 用 `-e` 传密码 | `docker inspect` 可见 | 用 secrets | 第 30 章 |
| CI 用 `-it` | 卡住 | CI 不用 -it | 官方 |
| `--name` 重名 | 创建失败 | 先删或换名 | 实测 |
| 不加 `--rm` 跑一次性任务 | 容器堆积 | 加 `--rm` | 第 11 章 |
| 只写 `-p 8080` | 随机宿主端口 | 写全 `宿主:容器` | 实测 |
| `-d` 后不看日志 | 不知为何退出 | `docker logs` | 第 10 章 |
| 端口冲突 | `port is already allocated` | 换端口或 `ss -lntp` | 第 17 章 |
| 认为 `run` 是长期运行 | 主进程退出即停 | 用长驻进程 | 实测 |
| 跳过退出码 | CI 漏判 | 检查 `$?` | 实测 |

## 6. 最佳实践

一次性任务一律加 `--rm`；长驻服务用 `-d --name --restart unless-stopped`；端口按最小暴露原则绑定。
