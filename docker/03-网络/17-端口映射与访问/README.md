# 17 端口映射与访问

## 一句话结论

`-p 宿主:容器` 通过 iptables **DNAT** 把宿主端口转发到容器端口。默认绑 `0.0.0.0`（全网可访问），`127.0.0.1:8080:80` 只绑本机。容器内服务必须监听 `0.0.0.0`，否则映射进不来。

## 最小可运行案例

```bash
docker run -d -p 8080:80 nginx:alpine          # 宿主 8080 → 容器 80
docker run -d -p 127.0.0.1:8081:80 nginx:alpine  # 只本机
docker run -d -P nginx:alpine                    # 随机分配
docker port <容器>                               # 查映射
```

## 映射语法

| 写法 | 含义 |
| --- | --- |
| `-p 8080:80` | 宿主 8080 → 容器 80，绑 0.0.0.0 |
| `-p 127.0.0.1:8080:80` | 只绑回环 |
| `-p 80` | 容器 80 映射到随机宿主端口 |
| `-p 8080:80/udp` | UDP |
| `-p 8080:80 -p 8443:443` | 多端口 |
| `-P` | 按镜像 EXPOSE 随机分配 |

## 数据流

```text
外部请求 → 宿主 eth0:8080
  → iptables PREROUTING/OUTPUT DNAT
  → 容器 172.17.0.x:80
  → 回包 SNAT（MASQUERADE）
```

## 最容易踩的坑

| 现象 | 原因 | 解决 |
| --- | --- | --- |
| 映射了但访问不到 | 应用只监听 127.0.0.1 | 改监听 0.0.0.0 |
| 启动报端口占用 | 宿主端口已被用 | 换端口，`docker port` 查现有 |
| Docker 29 报 `failed to set up container networking` | 端口冲突的新文案 | 同样是端口冲突，换端口 |
| 公网能直接访问 | 默认绑 0.0.0.0 | 加 `127.0.0.1:` 前缀或防火墙 |
| 容器访问宿主服务失败 | 用了 localhost | 用 `host.docker.internal` 或网关 IP |
| 改了 -p 需要重建容器 | 端口在创建时确定 | 删容器重建 |
| 同一宿主端口映射两次 | 冲突 | 只能一个容器占用 |
| 容器内端口写错 | 与 EXPOSE 无关，看实际监听 | `docker port` + 容器内 `ss` |
