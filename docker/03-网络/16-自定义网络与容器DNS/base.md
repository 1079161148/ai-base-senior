# 16 自定义网络与容器 DNS · 完整版

## 0. 怎么用

跑 10/10。本章真实验证"容器名可解析、网络隔离、connect 后互通、disconnect 后恢复隔离"。

## 1. 概念

自定义 bridge 网络 = 独立网段 + 内嵌 DNS + 名称空间隔离。它解决默认 bridge 的两个痛点：无名称解析、所有容器混在一起。

## 2. 机制

```text
network create mynet
  → 新建网桥 br-xxxx，分配子网
  → 启动内嵌 DNS（容器内 127.0.0.11）
容器接入
  → 在 DNS 中注册 容器名 与 --network-alias
  → 同网络内可直接用名字解析
```

## 3. 逐个拆解（本机实测）

| 操作 | 实测结果 |
| --- | --- |
| `network create --subnet 172.28.0.0/16` | 子网 = `172.28.0.0/16` |
| 同网络 `ping 容器名` | 成功 |
| 同网络 `ping 别名 api` | 成功 |
| `/etc/resolv.conf` | `nameserver 127.0.0.11` |
| 跨网络 ping | `bad address`（隔离） |
| `network connect` 后 ping | 成功 |
| `network disconnect` 后 ping | 又失败 |
| `len .Containers` | 2 |
| 容器 IP | `172.28.0.x` |

## 4. 边界条件

- 只有**自定义网络**有 DNS，默认 bridge 没有。
- 一个容器可加入多个网络，每个网络里各自解析。
- 同一网络内**容器名与别名都不能重复**，否则解析不确定。
- 默认 DNS 的 TTL 很短，容器重建后 IP 变化能被及时感知。
- 自定义子网不要与公司内网/云 VPC 重叠，否则路由混乱。

## 5. 注意事项对照表

| 错误做法 | 现象 | 正确做法 | 依据 |
| --- | --- | --- | --- |
| 用默认 bridge 做服务发现 | 名字解析失败 | 自定义网络 | 实测 |
| 记 IP 连接 | 重启失效 | 用容器名 | 实测 |
| 别名重复 | 解析到不确定容器 | 唯一别名 | 实测 |
| 子网与内网重叠 | 路由冲突 | 规划网段 | 官方 |
| 用 `--link` 做连接 | 已废弃 | 自定义网络 | 官方 |
| 跨网络不 connect | 连不上 | 同网或 connect | 实测 |
| 认为 DNS 立即生效 | 刚启动偶发失败 | 短暂重试 | 实测 |
| 生产用默认 bridge | 难管理 | 自定义网络 | 最佳实践 |
| 不查 Contaniers 数 | 排障盲目 | inspect 查看 | 实测 |
| 跳过验收 | 网络认知错 | 10/10 再走 | 实测 |

## 6. 最佳实践

每个项目一个自定义网络，容器名即服务名；需要外部访问的才开端口映射（第 17 章）；子网提前规划，避免与内网冲突。
