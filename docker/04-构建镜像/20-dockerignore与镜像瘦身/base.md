# 20 .dockerignore 与镜像瘦身 · 完整版

## 0. 怎么用

跑 7/7。本章用随机数据（不可压缩）真实验证 ignore 与"跨层删除留幽灵"。

## 1. 概念

构建上下文是 `docker build .` 里那个 `.` 目录，会被**整个发送**给 daemon。`.dockerignore` 在发送前过滤，既省时间也省镜像。

层不可变：`RUN rm` 只是在新层里记一条"删除"，下面的层仍有原文件，镜像总大小不减。

## 2. 机制

```text
docker build .
  → 打包上下文 → .dockerignore 过滤 → 发送 daemon
  → 每条 RUN/COPY 提交一层（快照）
RUN A: 10MB 文件 → 层1 含 10MB
RUN B: rm 文件   → 层2 只记录删除标记，层1 的 10MB 仍在
总大小 ≈ 10MB + 基础层
```

## 3. 逐个拆解（本机实测）

| 实验 | 结果 |
| --- | --- |
| 无 ignore，5MB 文件 | 镜像 8MB，`ls /app` 含 `blob.bin` |
| 加 ignore 后 | 镜像 3MB，不含 `blob.bin`，缩减 5MB |
| 同一 RUN 建 10MB + 删 | 3MB（无残留） |
| 跨 RUN 建 10MB 再删 | 13MB（残留 10MB） |

## 4. 边界条件

- `.dockerignore` 只影响上下文传输，不影响镜像内已有文件。
- 注意 `.Size` 是**压缩后**大小：全零数据会被 gzip 压到几乎为 0，看不出差异；要验证瘦身得用随机数据。
- 跨层删除不减小镜像，这是分层设计决定的，不是 bug。
- `COPY` 无法复制上下文之外的文件（多阶段构建除外，见第 21 章）。
- 忽略 `.env` 不等于密钥安全，运行时仍可能被误打进镜像。

## 5. 注意事项对照表

| 错误做法 | 现象 | 正确做法 | 依据 |
| --- | --- | --- | --- |
| 不用 `.dockerignore` | 构建慢、镜像大 | 加忽略规则 | 实测 |
| 跨层 rm | 镜像不减 | 同 RUN 内删 | 实测 |
| 用全零文件测体积 | 看不出差异 | 用随机数据 | 实测 |
| 把 `.env` 打进镜像 | 密钥泄露 | ignore + secrets | 安全 |
| `COPY . .` | 带进 node_modules/.git | 精确 COPY | 实测 |
| apk/apt 不清理 | 缓存残留 | `--no-cache` 或 rm | 官方 |
| 认为 ignore 也删镜像内文件 | 理解错 | 只影响上下文 | 官方 |
| 忘记重新 build | 改动未生效 | 重建 | 实测 |
| 用 `--no-cache` 当瘦身手段 | 只是不用缓存 | 真正手段是 ignore/多阶段 | 第 19 章 |
| 跳过验收 | 幽灵数据不知 | 7/7 再走 | 实测 |

## 6. 最佳实践

`.dockerignore` 至少排除 `.git`、`node_modules`、`dist`、`*.log`、`.env`；安装类命令一律"装完即清"；最终镜像用多阶段构建。
