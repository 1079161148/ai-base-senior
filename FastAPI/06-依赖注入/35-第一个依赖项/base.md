## 1. 概念：依赖 = 可复用的「参数 + 前置逻辑」

| 没有依赖 | 有依赖 |
| --- | --- |
| 每个端点重复写 `skip/limit` | 写一次 |
| 重复写鉴权判断 | 写一次，还能复用 |
| 校验规则散落 | 集中在函数里 |
| 想换实现要改 N 处 | 换一个函数 |

依赖的两个产出：**解析参数** + **返回注入值**。副作用（鉴权、限流）是附加能力。

## 2. 机制：解析顺序

```text
请求
 → 遍历 dependant.dependencies（递归，深度优先）
      解析每个依赖自己的参数（query/header/path/body）
      调用依赖函数 → 得到返回值
 → 解析端点自身参数
 → 调用端点函数
```

| 事实 | 说明 |
| --- | --- |
| 依赖参数与端点参数合并 | 同一个 OpenAPI `parameters` 列表 |
| 同名参数 | 后端按各自声明解析，容易混淆（建议避免）|
| 依赖抛异常 | 立即中断，端点不执行（实测）|
| 返回值缓存 | 默认同一请求内缓存（第 37 章）|
| 依赖可嵌套 | 第 37 章 |

### 实测：OpenAPI 形态

`/items` 的 `parameters`：`q`、`skip`、`limit`，全部 `in: query`，`description` 原样保留；**没有** `requestBody`。

## 3. API 逐个拆解

### 3.1 三种写法

| 写法 | 示例 | 评价 |
| --- | --- | --- |
| `Annotated` | `c: Annotated[dict, Depends(fn)]` | **推荐**，类型与依赖同处 |
| 默认值 | `c: dict = Depends(fn)` | 旧写法，仍广泛存在 |
| 别名（第 38 章）| `c: CommonsDep` | 复用 Annotated |

三者行为一致；`Annotated` 的好处是不与「参数默认值」语义冲突。

### 3.2 依赖签名能力

依赖函数可以声明：

| 类型 | 示例 |
| --- | --- |
| query | `q: str = Query(None)` |
| header | `x: str = Header(None)` |
| path | 需要同名路径参数（少见）|
| body 模型 | `item: Item`（整请求体）|
| `Request` | 读原始请求 |
| 其他依赖 | `Depends(other)` |

实测：`client_info` 只声明 `Request`，端点签名里看不到它。

### 3.3 依赖的默认值

```python
async def common_parameters(limit: int = Query(10, ge=1, le=100)) -> dict: ...
```

默认值写在**依赖函数**上；写在 `Annotated[T, Depends(fn)] = ...` 处会被忽略或冲突。

## 4. 边界条件

### 4.1 依赖内校验（实测）

`?limit=200` → 422，`loc=["query","limit"]`，`type=less_than_equal`。**不会**报「依赖出错」，对客户端完全透明。

### 4.2 依赖内抛错（实测）

401 + `WWW-Authenticate`，body 只有异常信息，没有端点的 `route_ran` 字段 → 端点未执行。

### 4.3 依赖与路径参数

`/items/{item_id}` + 依赖共存正常（实测 `item_id=7, limit=2`）。参数顺序无要求。

### 4.4 执行次数（实测）

`/a` 与 `/b` 各请求一次 → 依赖调用 2 次。依赖结果**不跨请求缓存**；同一请求内多次 `Depends` 同一函数会缓存（第 37 章）。

### 4.5 并发

依赖函数按请求调用，不要在模块级变量里存「当前请求」状态（并发会串）。要存就用 `request.state`。

### 4.6 性能

| 依赖做的事 | 影响 |
| --- | --- |
| 纯计算/参数整理 | 可忽略 |
| 查库（每请求）| 需缓存/连接池（第 40 章）|
| 外部 HTTP | 建议 `async` + 超时 |
| 大对象构造 | 每请求一份 |

### 4.7 OpenAPI 与文档

依赖参数会出现在端点的 `parameters` 里，`description`/`ge`/`le` 等约束也会保留。这意味着**依赖就是端点的公开契约的一部分**，改依赖签名等于改 API。

## 5. 注意事项与新手错误对照表

| 错误写法 / 操作 | 现象 | 正确写法 | 依据 |
| --- | --- | --- | --- |
| `Depends()` 空参数 | 定义期报错 | 传 callable | 实测 |
| `Annotated[...] = Depends(fn)` 再加默认值 | 冲突/忽略 | 默认值放 fn 上 | `[D1]` |
| 依赖里 `return {"error": ...}` | 端点继续跑 | `raise` | 实测 |
| 依赖里写全局变量 | 并发串数据 | `request.state` | `[D2]` |
| 同步依赖里阻塞 IO | 阻塞事件循环 | `async def` | `[D2]` |
| 依赖返回巨大对象 | 每请求构造 | 只返回必要字段 | `[D3]` |
| 依赖参数名与端点重名 | 行为难预测 | 改名/合并 | `[D1]` |
| 以为依赖只执行一次（全局）| 每请求都执行 | 用缓存依赖 | 第 37 章 |
| 把鉴权写成端点内 if | 重复且易漏 | 依赖 | `[D1]` |
| 依赖里捕获所有异常 | 掩盖错误 | 只处理预期错误 | `[D2]` |
| 依赖里改 `response` | 需注入 `Response` | 明确返回值 | 第 24 章 |
| 依赖里 `await` 未加 async | 语法错 | `async def` | `[D1]` |
| 用依赖做「请求后」逻辑 | 它在端点前执行 | 用 `yield`（第 40 章）|
| 依赖无返回却被赋值 | `None` 注入 | 明确返回 | `[D1]` |
| 依赖做重校验又写模型校验 | 重复 | 交给 Pydantic | `[D1]` |
| 同一函数既当依赖又直接调用 | 参数需手填 | 分离职责 | `[D3]` |
| 依赖里读 body | 可能已消费 | 用模型参数 | `[D2]` |
| 依赖顺序影响结果却没注释 | 隐性耦合 | 显式依赖链 | 第 37 章 |
| 依赖返回 `None` 却被当值用 | 端点拿到 `None` | 明确返回值 | `[D1]` |

## 6. 最佳实践与编码建议

### 6.1 依赖粒度

| 粒度 | 例子 | 建议 |
| --- | --- | --- |
| 参数整理 | 分页 | 推荐，纯函数 |
| 鉴权 | 解 token → 用户 | 推荐（第 43 章）|
| 资源加载 | 按 id 查库并 404 | 推荐（第 36 章类依赖）|
| 业务编排 | 下单流程 | 不推荐，放服务层 |

### 6.2 编码建议

| 建议 | 说明 |
| --- | --- |
| 依赖保持纯函数 | 便于测试 |
| 参数用 `Annotated` | 类型清晰 |
| 异常用 `HTTPException`/业务异常 | 第 31–32 章 |
| 返回值小而稳定 | 避免每次构造大对象 |
| 命名体现用途 | `common_parameters` 而非 `dep1` |
