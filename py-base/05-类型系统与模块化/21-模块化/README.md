## 0. 依据标注约定

本章 `` `[Rn]` `` 仅在本章有效，索引见第 7 节；「未直连核对」的链接按官方文档通行表述整理。

## 1. 概念

- **模块**就是一个 `.py` 文件，模块名是 `__name__`；**包**是含 `__init__.py` 的目录（也有命名空间包）。`[R1]` `[R2]`
- `import m` 会查找、加载并执行模块代码，把模块对象绑定到本地名字；模块**只执行一次**，后续导入从 `sys.modules` 取缓存。`[R1]` `[R2]`
- 搜索路径来自 `sys.path`：脚本所在目录、`PYTHONPATH`、标准库与 site-packages。`[R1]`
- `from m import x` 绑定的是名字，不是「复制一份」；`import m` 后用 `m.x` 更不易命名冲突。`[R1]`
- 绝对导入优先；显式相对导入 `from . import sibling` 适合复杂包布局，标准库代码应避免复杂布局。`[R3]`
- 直接运行脚本时 `__name__ == "__main__"`，被导入时等于模块名；因此用 `if __name__ == "__main__":` 保护入口。`[R1]`
- `import` 语句应放在文件顶部（模块 docstring 之后），按「标准库 / 第三方 / 本地」分组，组间空行；避免 `import *`。`[R3]`

## 2. 注意事项

1. **不要 `from x import *`**，命名空间不可控。`[R3]`
2. **模块名别与标准库同名**（`json.py`、`typing.py`），会遮蔽标准库。
3. **`import` 会执行模块顶层代码**，重副作用要放进函数或 `__main__` 保护。
4. **循环导入**通常是分层设计有问题，抽公共模块而不是靠延迟导入硬绕。
5. **相对导入只在包内可用**，直接运行子模块会失败。`[R1]`
6. **不要靠改 `sys.path` 拼接路径**，用包结构与可编辑安装（第 29 章）。

## 3. 边界考虑

| 边界 | 说明 | 依据 |
| --- | --- | --- |
| 单次执行 | 模块级状态在进程内共享，重载需 `importlib.reload`（谨慎） | `[R2]` |
| 命名空间包 | 无 `__init__.py` 也可成包，但行为与普通包不同 | `[R2]` |
| 循环导入 | 顶层互相依赖会拿到半初始化模块 | `[R1]` |
| 路径与部署 | `sys.path` 随启动方式变化，部署时用包安装而非相对路径（第 29 章） | `[R1]` |

## 4. 最佳实践

1. **按职责拆模块**：编排 / 工具 / 模型客户端 / 出入口（第 01 章）。
2. **公共 API 用 `__all__` 明确导出**。`[R3]`
3. **绝对导入为主**，包内才用相对导入。`[R3]`
4. **脚本入口用 `main()` 函数 + `__main__` 保护**，便于测试与复用。
5. **依赖方向单向**，底层模块不反向依赖上层。

## 5. 最佳编码建议

- **import 分组、每组间空行、每行一个 import**。`[R3]`
- **模块名短小全小写**，必要时下划线。`[R3]`
- **注释解释「为什么这样分层」**。`[R3]`
- **显式优于隐式、不做预留扩展**（第 01 章）。

## 6. 编码示例

`examples/module_demo.py`：

```python
"""第 21 章示例：模块、导入与 __name__。"""

import os
import sys

print("模块名:", __name__)
print("入口判断:", __name__ == "__main__")
print("os 来自:", os.__file__)
print("搜索路径首项:", sys.path[0])
```

运行：

```powershell
cd 'E:\ai-agent-study\py-base\05-类型系统与模块化\21-模块化'
python examples/module_demo.py
```

关键输出：`模块名: __main__`、`入口判断: True`；`os` 来自 `Python312\Lib\os.py`，印证标准库随解释器分发（第 02 章）。`[R1]`
