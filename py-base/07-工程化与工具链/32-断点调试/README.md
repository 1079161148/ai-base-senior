## 0. 依据标注约定

本章 `` `[Rn]` `` 仅在本章有效，索引见第 7 节；「未直连核对」的链接按官方文档通行表述整理。**示例不进入交互式调试器**。

## 1. 概念

- `breakpoint()` 是标准入口：默认调用 `pdb.set_trace()` 进入交互式调试；用环境变量 `PYTHONBREAKPOINT=0` 可**全局禁用**，不必改代码。`[R1]` `[R2]`
- `python -m pdb script.py` 从第一行开始调试；`pdb` 支持断点、单步、查看变量与栈帧。`[R1]`
- 常用命令 `[R1]`：`h`（帮助）、`l`（列出源码）、`n`（下一步）、`s`（进入函数）、`c`（继续）、`p expr`（打印表达式）、`pp expr`（美化打印）、`w`（栈回溯）、`b`（设断点）、`q`（退出）。
- `inspect.currentframe()` 可只读获取当前栈帧信息（函数名、行号），是调试器与日志上下文的基础。`[R3]`
- 生产环境**不能**靠交互式断点：用 `logging` 分级记录、请求/任务 ID 串联、指标与 trace（第 22 章）。`[R4]`
- 调试完必须清理 `breakpoint()` / 临时 print，不把调试代码提交进仓库（第 01 章）。

## 2. 注意事项

1. **不要在生产镜像里留 `breakpoint()`**，会挂起进程等待 stdin。`[R2]`
2. **敏感数据不进日志、不进调试输出**（第 01 章安全底线）。`[R4]`
3. **别用 `print` 代替日志**：缺少级别、时间与上下文。`[R4]`
4. **并发/异步调试要给任务标识**，否则日志交错无法还原（第 27–28 章）。
5. **不要靠反复改代码试错**，先用断点看真实状态。
6. **异常信息要可操作**，保留原始 traceback（第 16 章）。

## 3. 边界考虑

| 边界 | 说明 | 依据 |
| --- | --- | --- |
| 交互式限制 | 无 stdin 的容器/CI 里 pdb 不可用 | `[R1]` |
| 多线程/异步 | 断住一个任务不等于停住整个系统（第 24–28 章） | `[R1]` |
| 优化与内联 | 优化后的代码行号/变量可见性可能变化 | `[R1]` |
| 远程调试 | 涉及端口与凭据，必须限内网、用完关闭 | 安全底线 |

## 4. 最佳实践

1. **先复现、再最小化、后断点**：能稳定复现的问题修起来最快。
2. **用条件断点处理循环里的第 N 次**，别手动 `c` 几百次。`[R1]`
3. **日志分级 + 结构化上下文**，面向用户只给可操作提示（第 22 章）。
4. **给外部调用加超时与 trace 标识**（第 27 章）。
5. **修复后补一个回归测试**，把 bug 变成防线。

## 5. 最佳编码建议

- **注释解释「为什么加这个日志/断言」**。`[R4]`
- **不提交调试代码、临时打印、被注释的死代码**（第 01 章）。
- **命名表达意图、失败要快**（第 01 章）。
- **密钥与用户数据不出现在任何诊断输出中**（第 01 章）。

## 6. 编码示例

`examples/debug_demo.py`（只读获取栈帧信息，不进入交互式调试）：

```python
"""第 32 章示例：只读获取调用栈信息。"""

import inspect

def tool_call(name):
    """返回当前栈帧中的函数名 [R3]。"""
    frame = inspect.currentframe()
    return {"function": frame.f_code.co_name, "argument": name}

print("栈帧:", tool_call("search"))
```

运行：

```powershell
cd 'E:\ai-agent-study\py-base\07-工程化与工具链\32-断点调试'
python examples/debug_demo.py
```

关键输出：`栈帧: {'function': 'tool_call', 'argument': 'search'}`——调试器展示的正是这类栈帧信息。`[R3]`

交互式调试的命令片段（**由你在终端手动执行**，本课不运行）：

```powershell
python -m pdb examples/debug_demo.py
```

进入后依次可用 `l`、`n`、`p`、`c`、`q`；依据 `[R1]`。
