# 01 必看导言：为什么学 Python，学什么，不学什么

> 本章是整门课的方向说明。**先划边界，再学语法**：Python 的知识半径远大于 Agents 开发所需，不先确定「不学什么」，很容易在语法细节里迷路。

| 项 | 内容 |
| --- | --- |
| 前置依赖 | 无 |
| 本章目标 | 说清 Agents 开发中 Python 的定位、必学范围与跳过范围 |
| 毕业标准 | 能按目标岗位给出自己的语言路线；能对本教程 32 章说出「必学 / 按需 / 跳过」的判断；能解释服务端与客户端的职责边界 |
| 编码要求 | 能运行 `examples/agent_round.py`，并说出四个阶段分别对应哪类职责 |

## 1. 概念

### 1.1 开发 Agents 的两条语言路线

给定资料的结论：目前开发 Agents 主要有 `Python` 与 `TypeScript` 两种语言。

| 维度 | Python | TypeScript |
| --- | --- | --- |
| AI 生态 | ★★★★★ | ★★★ |
| 学习内容 | ★★★★★ | ★★★ |
| 优先场景 | 服务端 | 客户端 |

> 星级引自给定大纲资料，是**经验性评价**，不是可度量的客观指标；资料也没有说明「学习内容」的口径。两种解读都成立：
>
> - 指**学习资源丰富度** → Python 占优；
> - 指**需要掌握的知识量** → Python 的 5 星是成本，不是优势。
>
> 本课按第二种解读处理：正因为 Python 侧要学的东西多，**「不学什么」比「学什么」更需要先定**。
>
> 另需注意时效：TypeScript 侧的 Agent 框架与工具链在快速补齐，星级差距会随生态变化，别把它当成长期不变的选型依据。

### 1.2 为什么服务端 Agent 偏 Python

不是语言能力差异（两边都能发 HTTP、都能调模型 API），而是**运行时位置 + 生态分布**：

- **生态**：主流模型 SDK、数据处理库、Agent 编排框架、评测与可观测性工具多优先提供 Python 接口，服务端集成成本最低。
- **运行时**：服务端不依赖浏览器，Python 可直接持有凭据、访问本地文件与进程、跑长任务；这些在浏览器沙箱里受限制。
- **工程配套**：数据脚本、离线评测、任务队列常与 Agent 服务同仓，Python 一侧衔接更顺。

反过来，客户端偏 TypeScript 是因为**它就处在浏览器 / Node 运行时里**：交互、流式渲染、本地权限、与既有前端工程共享类型和构建链，换语言反而是负担。

### 1.3 职业路线映射

| 目标角色 | 主语言 | 辅语言 | 重点 | 明确不做 |
| --- | --- | --- | --- | --- |
| 前端工程师 | TypeScript | 能读懂 Python 服务端的接口契约 | 客户端 Agent UI、流式输出、工具调用的前端侧 | 不深入元类、描述符、C 扩展 |
| Agents 应用工程师 | Python | 能读懂 TypeScript 的接口契约 | 服务端编排、工具执行、上下文、评测、可观测性 | 不深入 DOM/CSS/前端框架 |
| AI 全栈工程师 | 两者 | — | 两端职责 + 边界接口 | 不要两条线同时从零并行 |

**对「最好都学」的修正**：都学 ≠ 同时学。建议先按目标岗位把一条线学到能产出项目，再补另一条线的**阅读能力**（看懂接口契约与错误处理即可），最后才补写的能力。两条线同时从零开始，常见结果是两边都停在语法层。

**一句话结论**：Python 与 TypeScript 是**分工维度**，不是优劣维度；选型依据是代码跑在哪一端，而不是哪门语言更强。

## 2. 什么要学

### 2.1 按本教程模块划定的范围

| 模块 | 章节 | 优先级 | 对 Agents 开发的用途 |
| --- | --- | --- | --- |
| 00 入门与环境 | 01–04 | 必学 | 环境可复现、基本语法、容器（工具参数与结果几乎都是容器） |
| 01 函数与作用域 | 05–07 | 必学 | 工具函数、回调、闭包；`lambda` 只需读懂 |
| 02 面向对象基础 | 08–11 | 必学 | 读懂 SDK 里的类、实例、可调用对象 |
| 03 面向对象进阶与元编程 | 12–15、19 | 按需 | 装饰器与魔法方法**必学**（框架代码到处都是）；描述符、ABC、元类以**读懂**为目标 |
| 04 异常与核心协议 | 16–18 | 必学 | 模型调用失败、超时、重试；生成器处理流式输出；上下文管理器管连接 |
| 05 类型系统与模块化 | 20–23 | 必学 | 类型标注是大型 Agent 项目的可维护性底线；模块化拆编排 / 工具 / 客户端 |
| 06 并发与异步 | 24–28 | 必学 | 并发调用多个工具或模型是 Agent 的性能核心；事件循环、Future、协程是异步框架的地基 |
| 07 工程化与工具链 | 29–32 | 必学 | 依赖锁定、构建发布、断点调试（排查 Agent 行为必备） |

### 2.2 学到什么程度（三层目标）

| 层级 | 要求 | 对应内容 |
| --- | --- | --- |
| 能写 | 独立实现工具函数、编排流程、错误处理、异步调用 | 00 / 01 / 02 / 04 / 05 / 06 模块 |
| 能读懂 | 看框架源码不卡壳，知道装饰器 / 描述符 / 元类在做什么 | 03 模块 |
| 能设计 | 决定模块边界、依赖方向、并发模型与可观测性埋点 | 05 / 06 / 07 模块 |

**把「能读懂」和「能写」分开**是本章最重要的建议：元类、描述符这类机制，Agents 应用工程师绝大多数工作日只需要读懂，不需要自己造。

### 2.3 顺序上的连贯性

先语法与容器 → 函数与作用域 → 对象模型 → 异常与协议 → 类型与模块化 → 异步并发 → 工程化。前一层是后一层的词汇表：没搞懂函数就写不出装饰器，没搞懂迭代器就看不懂生成器，没搞懂生成器就很难理解异步流式输出。

> 大纲有两处编号顺序与认知顺序不一致，本课按认知顺序讲、但保留原编号：`12-元类` 实际放在 `13/14/15/19` 之后学；`28-多线程与多进程` 先于 `24–27` 异步链建立并发直觉。

## 3. 什么不学

### 3.1 明确跳过

| 不学项 | 理由 | 例外（何时回头学） |
| --- | --- | --- |
| Python 写浏览器前端（DOM/CSS） | 客户端是 TypeScript 的主场，Python 侧无运行时优势 | 无 |
| 桌面 GUI（Tkinter / PyQt 等） | 与 Agents 服务端开发无关 | 要交付本地桌面客户端时 |
| 数值 / 科学计算深入（NumPy 矩阵运算、`scipy` 全家桶） | Agents 应用主要处理文本、工具 I/O 与状态，不是数值计算；基础表格读写按需查即可 | 做 RAG 数据处理、评测指标或模型训练时 |
| 模型训练 / 微调框架 | 属于另一条学习路线，与「应用工程师」职责不同 | 岗位转向算法 / 训练时 |
| Web 全栈框架深入（模板引擎、ORM、后台管理） | Agent 服务通常只暴露少量 HTTP / SSE 接口 | 要独立交付完整 Web 产品时 |
| Python 2 及 2/3 兼容写法 | 已停止维护，学了是负担 | 维护遗留系统 |
| CPython 源码、C 扩展、手写内存管理 | 应用层瓶颈几乎都在 I/O 与模型调用 | 做推理运行时 / 性能工程时 |
| 语法糖收集、炫技式一行流 | 降低可读性，不解决 Agent 的真实难点 | 无 |
| 手写网络协议 / 序列化底层 | 用成熟库即可，不重复造轮子 | 做基础设施时 |

### 3.2 灰色区：知道机制，但不主动使用

`12-元类`、`15-描述符`、`19-ABC` 属于「读懂框架必需、自己写要克制」：

- **该学**：能解释 `@dataclass`、`@property`、SDK 里的抽象基类在做什么。
- **不该做**：在业务代码里用元类做「自动注册一切」的隐式魔法，或用描述符隐藏状态变更。
- **判据**：显式优于隐式。隐式机制每多一层，调试 Agent 行为时就多一层不可见状态。

### 3.3 常见误区

1. **把星级当结论**：5 星 / 3 星是选型线索，不是项目约束；真实约束来自团队栈、部署环境与招聘需求。
2. **用语言选型掩盖架构问题**：Agent 的难点在编排、上下文管理、工具契约、失败恢复与评测，换语言不会自动解决。
3. **先学全语法再动手**：语法是工具，不是前置条件；跑通一个最小 Agent 闭环后再回头补语法，理解会快得多。
4. **把 Python 当 TypeScript 写**：照搬前端的目录约定、命名风格、错误处理习惯，会得到两边都不像的代码；遵循语言与项目既有约定。

## 4. 注意事项

- **时效**：AI 生态变化快，本章所有「生态占优」的判断都有有效期；具体选型时重新核对当下库的维护状态与类型完备度。
- **版本**：本课以 Python 3 为准，解释器版本、虚拟环境、依赖锁定的具体做法在第 02 章，本章不涉及。
- **安全底线**：服务端持有模型 API Key 与用户数据，密钥一律走环境变量 / 配置中心，不硬编码、不进日志、不返回前端。本课所有章节都适用。
- **不要跳章做练习**：本章示例刻意只用变量与 `print()`，是为了不提前引入后续章节的语法。

## 5. 边界考虑

| 边界 | 说明 |
| --- | --- |
| 服务端 / 客户端不是语言的硬边界 | Node 同样能跑服务端 Agent，Python 也能写 CLI/TUI；「优先场景」是生态分布，不是能力限制 |
| 团队与部署会覆盖偏好 | 既有 TypeScript 全栈团队、边缘运行时、浏览器包体积限制，都可能让选型偏向 TypeScript |
| 混合架构是常态 | 常见形态是 TypeScript 前端 + Python Agent 服务，两侧通过 HTTP / SSE / WebSocket 等接口划分职责；先定接口契约，再各自实现 |
| 凭据与状态的归属 | 模型 Key、长任务状态、工具执行权限应留在服务端；客户端只拿必要的展示数据 |
| 并发模型的差异 | Python 的 GIL 与事件循环、TypeScript 的事件循环不是一回事；性能与并发结论留到 24–28 章，本章不下结论 |
| 学习投入的边界 | 「全栈都要学」的成本主要在第二门语言的**工程生态**（构建、依赖、测试、部署），不在语法；预算要按这个算 |

## 6. 最佳实践

1. **按岗位定主语言，按项目边界定辅语言**，一次只把一条线推进到能产出项目。
2. **先跑通最小闭环再补细节**：输入 → 模型决策 → 工具执行 → 输出，四步先串起来。
3. **先划模块边界再写实现**：编排 / 工具 / 模型客户端 / 出入口分开，避免一个脚本混所有职责。
4. **类型标注 + 静态检查前置**：Agent 项目的函数签名多是嵌套容器与可选值，不写类型，后期重构代价很高（第 20 章展开）。
5. **环境与依赖可复现**：虚拟环境 + 锁定依赖，保证「我这能跑」可迁移（第 02 / 30 章展开）。
6. **失败要快且明确**：模型超时、工具报错、格式不符要显式抛出或返回状态，禁止静默吞掉——静默失败在 Agent 里会变成难以定位的错误答案。

## 7. 最佳编码建议

- **命名表达意图**：`tool_result` 而非 `data` / `res2`；布尔量用 `is_` / `has_` / `can_` 前缀。
- **不可变优先**：能不重新赋值就不重新赋值；Agent 的状态集中管理，别散落在全局变量里。
- **配置外置**：API Key、模型名、超时时间走配置，不写在代码里；错误日志不打印敏感值。
- **外部输入必须校验**：工具参数来自模型输出，本质是不可信输入，服务端要独立校验（前端校验不算）。
- **注释解释「为什么」**：代码本身说明「做什么」；隐式约定、临时绕过、非直觉取舍才写注释。
- **不捕获后抛更模糊的异常**：丢失上下文会让线上排查失去线索。
- **不做预留扩展**：只写当前需要的抽象，同一逻辑重复三次以上再抽。

## 8. 编码示例

### 8.1 两种语言的同一件事（只读对照）

Python：

```python
message = "搜索今天的 AI 新闻"
print(message)
```

TypeScript：

```ts
const message = "搜索今天的 AI 新闻";
console.log(message);
```

语义等价，差别在运行时位置。**引出的不是语法问题，而是这一行代码跑在谁的进程里**：客户端的那行不能直接持有模型 Key，服务端的那行可以。

### 8.2 一个 Agent 回合的数据流（可运行）

`examples/agent_round.py` 只用变量、字符串与 `print()`，把四段职责用数据表达出来；注释标出后续由哪类知识替换成真实实现。

```python
"""第 01 章示例：一个 Agent 回合的数据流骨架。

只使用变量、字符串与 print()。本章尚未讲到函数、类与 import，
因此这里用「数据」而不是「逻辑」表达分层；后续章节会逐步把
这些占位替换成真实实现。

运行：
    python examples/agent_round.py
"""

# 1. 输入：来自客户端（TypeScript / 浏览器 / CLI）
user_message = "帮我查一下今天的 AI 新闻"

# 2. 计划：模型决定下一步动作（第 05 章函数、第 27 章异步编排）
plan = "调用 search 工具"

# 3. 工具结果：服务端执行工具后回填（第 11 章可调用对象、第 22/23 章库）
tool_result = "3 条相关新闻"

# 4. 输出：返回给客户端（第 21 章模块化、第 27 章异步 I/O）
answer = "找到 " + tool_result

print("用户输入:", user_message)
print("模型计划:", plan)
print("工具结果:", tool_result)
print("最终回答:", answer)
```

运行（第 02 章装好环境后）。`examples/` 是相对**本章目录**的路径，若停在 `py-base` 根目录直接执行，会报 `can't open file ... [Errno 2] No such file or directory`：

```powershell
# 写法 A：切到本章目录
cd 'E:\ai-agent-study\py-base\00-入门与环境\01-必看导言'
python examples/agent_round.py

# 写法 B：留在 py-base 根目录，写全相对路径
python '.\00-入门与环境\01-必看导言\examples\agent_round.py'
```

预期输出：

```text
用户输入: 帮我查一下今天的 AI 新闻
模型计划: 调用 search 工具
工具结果: 3 条相关新闻
最终回答: 找到 3 条相关新闻
```

> 本章刻意不写 `def`、`class`、`import`：它们分别在第 05、08、21 章系统展开。看懂「四段职责」即可，不要提前纠结实现。
