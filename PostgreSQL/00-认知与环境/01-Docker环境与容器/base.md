# 01 Docker 环境与容器 · 完整版

## 0. 怎么用

先照抄命令起容器，跑 8/8 验收，再读第 2 节理解端口映射。

## 1. 概念

容器把数据库进程、依赖和系统库打包。删容器只是删进程，数据在数据卷里。

## 2. 机制

```text
宿主机 127.0.0.1:54321 → Docker 端口映射 → 容器 127.0.0.1:5432
                                              ↓
                                   /var/lib/postgresql/data
                                              ↓
                                   宿主机 .pgdata
```

## 3. API 逐个拆解

| 命令/参数 | 作用 | 注意 |
| --- | --- | --- |
| `docker run -d` | 后台运行 | 不加会占住终端 |
| `--name` | 容器名 | 本教程 `pg16-study` |
| `-e POSTGRES_*` | 初始化环境变量 | 只在首次 initdb 生效 |
| `-p` | 端口映射 | 左宿主机，右容器 |
| `-v` | 数据卷 | 左宿主机，右容器 |
| `docker exec -it` | 交互式进入 | 需容器在跑 |
| `pg_isready` | 就绪探测 | 返回 accepting connections |

## 4. 边界条件

- 环境变量密码在容器**首次初始化**时写入，之后改环境变量无效。
- Windows 路径用正斜杠或双反斜杠。
- 端口 54321 若被占，换端口后必须同步改 `common.py` 的 `DSN`。

## 5. 注意事项对照表

| 错误写法 / 操作 | 现象 | 正确写法 | 依据 |
| --- | --- | --- | --- |
| 连 5432 | 连接拒绝 | 连 54321 | 实测 |
| 不挂卷 | 删容器丢数据 | 挂 `.pgdata` | 实测 |
| 改密码环境变量后重启 | 密码没变 | 重建容器或 `ALTER USER` | 实测 |
| Windows 选 ARM 镜像 | 无法运行 | AMD | 原仓库 01 |
| 不配镜像加速器 | 拉取慢 | Docker Engine 配 mirrors | 原仓库 01 |
| 容器没就绪就连接 | 连接失败 | `pg_isready` 轮询 | 实测 |
| 用 `postgres:16` 但本地只有 alpine | 拉取卡住 | 用已有 alpine | 实测 |
| 把容器内端口当宿主机端口 | 连不上 | 分清左右 | 实测 |
| 删 `.pgdata` | 全部章节数据丢失 | 保留 | 实测 |
| 直接 `docker rm -f` | 未提交事务回滚 | 先停应用 | 实测 |
| 容器名冲突 | run 失败 | 先 `docker rm -f` 旧容器 | 实测 |
| 用 root 连库 | 权限过大 | 用 admin | 实测 |
| 不跑 `EXPLAIN` 就建索引 | 不知道有没有用 | 第 21 章 | 原仓库 06 |
| 把 pgAdmin 当数据库 | 概念混淆 | 它只是客户端 | 原仓库 01 |
| 把 `postgres` 库当教程库 | 数据混在一起 | 用 `study` | 实测 |
| 跳过验收直接学下一章 | 环境坑积累 | 8/8 再走 | 实测 |
| 用 `SHOW` 查不到参数 | 参数名拼错 | `pg_settings` 兜底 | 实测 |
| 不设时区 | 时间显示混乱 | 用 `SHOW TimeZone` 确认 | 实测 |

## 6. 最佳实践

容器只负责进程，数据卷负责状态；升级镜像时删容器不删卷。
