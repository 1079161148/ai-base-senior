# 42 混合检索 · 完整版

## 0. 怎么用

跑 7/7。关键词检索保证精确匹配、向量检索保证语义相近，用 RRF 融合两路排名可取长补短。

## 1. 概念

本章聚焦「关键词 + 向量混合检索」，是 M06 向量数据库体系中的一环，建立在前面关系型基础之上。

## 2. 机制

```text
→ ILIKE / to_tsvector
→ <=>
→ RRF 1/(60+rank)
```

## 3. API 逐个拆解

| API | 作用 | 注意 |
| --- | --- | --- |
| `ILIKE / to_tsvector` | 关键词检索 | 见验收 |
| `<=>` | 向量检索 | 见验收 |
| `RRF 1/(60+rank)` | 排名融合 | 见验收 |
| `GIN + HNSW` | 两路索引 | 见验收 |

## 4. 边界条件

- 向量维度必须与模型一致，算子要求维度相同。
- 近似索引以少量召回换取速度，需用评测校准。
- 教学用可复现向量验证机制，生产须换真实 embedding 模型。

## 5. 注意事项对照表

| 错误做法 | 现象 | 正确做法 | 依据 |
| --- | --- | --- | --- |
| 中文用 simple 分词 | 词命中差 | ILIKE 或中文分词插件 | 实测 |
| 只做向量检索 | 精确词漏召回 | 加关键词路 | 实测 |
| 分数直接相加 | 量纲不同 | 用 RRF 按排名融合 | 实测 |
| 不建 GIN | 关键词慢 | 建 GIN 索引 | 实测 |

## 6. 最佳实践

先测正确性再测性能；每次调参都用固定评测集对比，避免凭感觉。
