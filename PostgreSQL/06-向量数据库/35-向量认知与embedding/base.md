# 35 向量认知与embedding · 完整版

## 0. 怎么用

跑 7/7。本章建立直觉：向量是语义坐标，距离代表语义相似度，pgvector 把这套能力装进 PostgreSQL。

## 1. 概念

传统数据库回答"值等于多少"，向量数据库回答"什么最像"。embedding 模型把非结构化数据映射到高维空间，语义相近的输入落在相近位置。

## 2. 机制

```text
文本 → embedding 模型 → 向量 [0.12,-0.33,...] → 存入 vector 列
查询 → 同一模型 → 查询向量 → ORDER BY 距离 LIMIT k → Top-K
```

关键点：查询和文档必须用同一个模型，否则向量不在同一空间，距离无意义。

## 3. 组件拆解

| 组件 | 作用 | 本章体现 |
| --- | --- | --- |
| `vector(n)` | 存储定长浮点向量 | `embedding vector(8)` |
| `<->` | L2 距离 | 最近邻排序 |
| `CREATE EXTENSION` | 启用 pgvector | `vector` |
| embedding | 文本转向量 | `fake_embedding` |

> 教学说明：本章用确定性的字符哈希向量代替真实 embedding 模型。它保证"共享字符多 → 距离近"，足以真实验证存储、距离、索引与排序机制；真实项目必须换成生产级 embedding 模型。

## 4. 边界条件

- 向量维度属于表结构，改维度要重建列。
- 距离算子要求维度一致，否则报错。
- 不同模型的向量不可混用。

## 5. 注意事项对照表

| 错误做法 | 现象 | 正确做法 | 依据 |
| --- | --- | --- | --- |
| 混用模型向量 | 结果无意义 | 同模型生成 | 实测 |
| 维度不匹配 | 插入报错 | 固定维度 | 实测 |
| 教学随机向量 | 相似度乱 | 可复现向量 | 实测 |
| 只存向量不存原文 | 无法展示 | 原文+向量同存 | 第 44 章 |
| 无 Top-K 限制 | 全表扫描 | LIMIT k | 第 41 章 |
| 不做归一化 | 余弦受长度影响 | 用 `<=>` | 第 38 章 |
| 以为距离=语义分 | 阈值乱设 | 用评测校准 | 第 45 章 |
| 百万行不建索引 | 查询慢 | IVFFlat/HNSW | 第 39/40 章 |
| 忽略元数据 | 无法过滤 | 元数据列+WHERE | 第 41 章 |
| 向量当普通数组 | 无算子 | 用 vector 类型 | 第 37 章 |
| 忘了建扩展 | 类型不存在 | CREATE EXTENSION | 实测 |
| 直接用 L2 比归一化向量 | 排序可近似但非最优 | 按场景选算子 | 第 38 章 |
| 不存模型版本 | 日后无法复现 | 记录版本元数据 | 第 43 章 |
| 跳过验收 | 直觉错 | 7/7 再走 | 实测 |

## 6. 最佳实践

先固定 embedding 模型与维度，再设计表结构；文档原文与向量同表存储，便于展示与溯源。
