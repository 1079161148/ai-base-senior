# 20 备份与恢复 · 完整版

## 0. 怎么用

跑 9/9，再看第 4 节理解不同备份方式的适用边界。

## 1. 概念

备份是数据安全的最后一道防线。没有恢复演练的备份等于没有备份。

## 2. 机制

```text
在线数据 → 逻辑导出(COPY/pg_dump) → 文件 → 逻辑导入 → 新库
        → 物理备份(pg_basebackup) → 时间点恢复(PITR)
```

## 3. API 逐个拆解

| API | 作用 | 注意 |
| --- | --- | --- |
| `CREATE TABLE AS` | 快照 | 不复制约束索引 |
| `COPY TO` | 导出 | CSV 可跨系统 |
| `COPY FROM` | 导入 | 列顺序要一致 |
| `pg_dump` | 完整逻辑备份 | 含结构 |
| `pg_restore` | 恢复 | 配合自定义格式 |

## 4. 边界条件

- CTAS 不复制主键、索引、约束。
- `COPY` 是行级流式，大表友好。
- 事务内 TRUNCATE 可回滚是 PG 特性。

## 5. 注意事项对照表

| 错误写法 / 操作 | 现象 | 正确写法 | 依据 |
| --- | --- | --- | --- |
| CTAS 当完整备份 | 丢约束索引 | pg_dump | 实测 |
| 不测恢复 | 备份无效 | 演练 | 实测 |
| 备份不记时间点 | 无法定位 | 记 timestamp | 实测 |
| 以为 TRUNCATE 不可回滚 | 认知错 | PG 可回滚 | 实测 |
| DDL 不在事务 | 无法撤销 | 包事务 | 实测 |
| CSV 编码不一致 | 导入乱码 | 统一 UTF8 | 实测 |
| 大表 CTAS | 长时间锁 | pg_dump | 实测 |
| 不校验备份完整性 | 恢复到坏数据 | count+校验和 | 实测 |
| 备份放同磁盘 | 磁盘坏全丢 | 异地 | 实测 |
| 恢复前不清库 | 数据混合 | 先 DROP | 实测 |
| COPY 列顺序错 | 数据错位 | 显式列名 | 实测 |
| 不设 ON_ERROR_STOP | 部分恢复 | psql 加参数 | 实测 |
| 备份含敏感数据 | 泄露 | 加密 | 实测 |
| 只用逻辑备份 | 大库恢复慢 | 结合物理备份 | 实测 |
| 不演练 PITR | 真出事手忙 | 定期演练 | 实测 |
| 跳过验收 | 恢复流程未验证 | 9/9 再走 | 实测 |
| 把 schema 当 database | 恢复范围错 | 分清层级 | 实测 |
| 不记录 pg_dump 版本 | 跨版本恢复失败 | 记录版本 | 实测 |

## 6. 最佳实践

定期 `pg_dump` + 恢复到空库演练；生产再加物理备份与 PITR。
