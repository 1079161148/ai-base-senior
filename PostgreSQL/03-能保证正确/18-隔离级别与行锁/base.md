# 18 隔离级别与行锁 · 完整版

## 0. 怎么用

跑 9/9，再看第 4 节理解锁与隔离的分工。

## 1. 概念

隔离级别是可见性规则，锁是并发控制手段。一个管读，一个管写冲突。

## 2. 机制

```text
SELECT ... FOR UPDATE → 取行级排他锁 → 其他事务写等待/失败 → 提交后释放
```

## 3. API 逐个拆解

| API | 作用 | 注意 |
| --- | --- | --- |
| `FOR UPDATE` | 排他锁 | 必须在事务内 |
| `FOR SHARE` | 共享锁 | 阻止写不阻止读 |
| `NOWAIT` | 立即失败 | 抛 LockNotAvailable |
| `SKIP LOCKED` | 跳过 | 队列场景 |
| `lock_timeout` | 等待上限 | 单位 ms |
| `pg_locks` | 锁视图 | 排查死锁 |

## 4. 边界条件

- autocommit 下的 `FOR UPDATE` 锁在语句结束就释放，没有意义。
- `SKIP LOCKED` 的结果不稳定，不适合要求完整性的查询。
- 会话级隔离设置会影响之后所有事务。

## 5. 注意事项对照表

| 错误写法 / 操作 | 现象 | 正确写法 | 依据 |
| --- | --- | --- | --- |
| autocommit 用 FOR UPDATE | 锁立即释放 | 显式事务 | 实测 |
| 不捕获 NOWAIT 异常 | 崩溃 | catch | 实测 |
| SKIP LOCKED 当完整查询 | 漏行 | 队列场景专用 | 实测 |
| 会话隔离不还原 | 污染后续 | 用后恢复 | 实测 |
| 锁顺序不一致 | 死锁 | 统一顺序 | 实测 |
| 不设 lock_timeout | 无限等待 | 设置上限 | 实测 |
| 锁全表 | 并发差 | 锁行 | 实测 |
| 事务里做慢 IO | 锁持有久 | 移出事务 | 实测 |
| 不查 pg_locks | 排查困难 | 查视图 | 实测 |
| 把 FOR SHARE 当 FOR UPDATE | 并发写仍可 | 分清 | 实测 |
| 高隔离级别滥用 | 吞吐低 | 按需 | 原仓库 05 |
| 不测锁释放后写入 | 不知道是否卡死 | 补用例 | 实测 |
| 用 SERIALIZABLE 代替锁 | 语义不同 | 按需选 | 实测 |
| 忘记 COMMIT/ROLLBACK | 锁不释放 | 显式结束 | 实测 |
| 连接泄漏 | 锁一直占 | close() | 实测 |
| 不记录 pid | 难排查 | pg_backend_pid | 实测 |
| 跳过验收 | 锁机制未验证 | 9/9 再走 | 实测 |
| 把锁当隔离级别 | 概念混 | 分清 | 实测 |

## 6. 最佳实践

扣库存这类「读-判断-写」必须先锁行；任务领取用 `SKIP LOCKED`。
