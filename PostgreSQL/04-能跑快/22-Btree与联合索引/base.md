# 22 B-tree 与联合索引 · 完整版

## 0. 怎么用

跑 10/10，再看第 4 节理解索引不是越多越好。

## 1. 概念

索引用空间换时间，代价是写入时要维护。

## 2. 机制

```text
CREATE INDEX → 建 B-tree → 写入时同步更新 → 查询时优化器决定是否使用
```

## 3. API 逐个拆解

| API | 作用 | 注意 |
| --- | --- | --- |
| `CREATE INDEX` | 建索引 | 会锁表（CONCURRENTLY 可缓解） |
| `UNIQUE INDEX` | 唯一 | 等价于唯一约束 |
| `WHERE` 部分索引 | 只索引子集 | 条件须匹配查询 |
| `lower(col)` 表达式索引 | 计算列 | 查询须写同样表达式 |
| `pg_stat_user_indexes` | 使用统计 | 找无用索引 |

## 4. 边界条件

- 联合索引 `(a,b)` 能服务 `a`、`a,b`，不能高效服务单独 `b`。
- Index Only Scan 需要 visibility map 干净，否则仍回表。
- `LIKE '%x'` 前缀通配符用不上 B-tree。

## 5. 注意事项对照表

| 错误写法 / 操作 | 现象 | 正确写法 | 依据 |
| --- | --- | --- | --- |
| 联合索引跳最左列 | 不用索引 | 调顺序 | 实测 |
| 每列单列索引 | 写放大 | 联合索引 | 实测 |
| 小表建索引 | 仍 Seq Scan | 数据足够 | 实测 |
| 索引列套函数 | 失效 | 表达式索引 | 实测 |
| 不加 ANALYZE | 统计旧 | 建后 ANALYZE | 通用实践 |
| 不删无用索引 | 写变慢 | 查使用统计 | 实测 |
| 部分索引条件不匹配 | 用不上 | 查询写相同条件 | 实测 |
| 唯一索引当约束 | 可以但语义弱 | 用 UNIQUE 约束 | 实测 |
| 生产直接 CREATE INDEX | 长时间锁 | CONCURRENTLY | 实测 |
| 索引 TEXT 大字段 | 体积大 | 前缀/哈希 | 实测 |
| 不测覆盖扫描 | 不知是否回表 | EXPLAIN | 实测 |
| 忽略索引膨胀 | 性能退化 | REINDEX | 第 25 章 |
| 用 SELECT * | 破坏覆盖索引 | 显式列 | 实测 |
| 不记录基线计划 | 优化无对照 | 存文本 | 第 21 章 |
| 跳过验收 | 索引可能无效 | 10/10 再走 | 实测 |
| 把 Bitmap 当 Index | 都属索引扫描 | 理解差异 | 实测 |
| 多列排序无索引 | 文件排序 | 建匹配索引 | 实测 |
| 不查索引大小 | 空间失控 | pg_relation_size | 实测 |

## 6. 最佳实践

按 `WHERE`/`JOIN`/`ORDER BY` 的实际查询建索引，建完用 EXPLAIN 验证。
