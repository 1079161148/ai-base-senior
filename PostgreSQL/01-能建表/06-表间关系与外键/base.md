# 06 表间关系与外键 · 完整版

## 0. 怎么用

先跑 10/10，再读第 4 节理解外键的取舍。

## 1. 概念

拆表减少冗余，外键把拆开的表重新连起来并强制完整性。

## 2. 机制

```text
插入子行 → 检查外键是否存在父行 → 存在则写入 → 不存在抛 ForeignKeyViolation
删除父行 → 按 ON DELETE 规则处理子行
```

## 3. API 逐个拆解

| API | 作用 | 注意 |
| --- | --- | --- |
| `REFERENCES` | 声明外键 | 列类型需一致 |
| `UNIQUE` | 保证 1:1 | 允许多个 NULL |
| `ON DELETE CASCADE` | 级联删 | 难追踪 |
| `ON DELETE SET NULL` | 置空 | 列须可 NULL |
| `ON DELETE RESTRICT` | 阻止删 | 不可延迟 |
| `ON DELETE NO ACTION` | 默认 | 可延迟检查 |
| `pg_constraint` | 约束目录 | `connamespace` 过滤 schema |

## 4. 边界条件

- 外键每次写都多一次索引查找，写入性能有代价。
- 分库分表后无法使用跨库外键。
- `CASCADE` 删除是隐式的，日志里不一定明显。

## 5. 注意事项对照表

| 错误写法 / 操作 | 现象 | 正确写法 | 依据 |
| --- | --- | --- | --- |
| 1:1 忘 UNIQUE | 变 1:N | 加 UNIQUE | 通用实践 |
| 1:N 加 UNIQUE | 变 1:1 | 去掉 | 通用实践 |
| M:N 不用中间表 | 无法表达 | 建中间表 | 通用实践 |
| 外键类型不一致 | 建表失败 | 类型一致 | 实测 |
| SET NULL 列 NOT NULL | 删除失败 | 允许 NULL | 实测 |
| CASCADE 滥用 | 误删数据 | 评估后使用 | 通用实践 |
| RESTRICT 与 NO ACTION 混用 | 语义混淆 | 默认用 NO ACTION | 通用实践 |
| 中间表无联合主键 | 重复关系 | 加 PRIMARY KEY | 通用实践 |
| 中间表无附加属性 | 丢失关系信息 | 加 enroll_date | 通用实践 |
| 不建外键索引 | 删除父表慢 | 给外键建索引 | 通用实践 |
| 循环外键 | 插入死锁 | 允许 NULL 分两步 | 实测 |
| 用业务键当外键 | 变更困难 | 用代理主键 | 通用实践 |
| 不查 pg_constraint | 靠猜 | 查元数据 | 实测 |
| 跨 schema 引用写错 | 找不到表 | 写全名 | 实测 |
| 大批量导入先建外键 | 慢 | 导完再建 | 实测 |
| 不设 ON DELETE | 默认 NO ACTION | 显式声明 | 实测 |
| ERD 只画表不画基数 | 关系不清 | 标 1/N/M | 通用实践 |
| 把 ERD 当物理模型 | 混淆逻辑与物理 | 分清层次 | 通用实践 |

## 6. 最佳实践

传统企业系统保留外键；超高并发分布式系统在应用层保证，但要有补偿校验。
