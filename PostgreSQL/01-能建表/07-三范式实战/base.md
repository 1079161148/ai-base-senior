# 07 三范式实战 · 完整版

## 0. 怎么用

先跑 9/9，再读第 4 节理解「范式是工具不是教条」。

## 1. 概念

范式用来减少冗余和更新异常。代价是查询要多 `JOIN`。

## 2. 机制

```text
乱表 → 1NF（原子）→ 2NF（消除部分依赖）→ 3NF（消除传递依赖）
                                              ↓
                                         JOIN 查回
```

## 3. API 逐个拆解

| API | 作用 | 注意 |
| --- | --- | --- |
| `PRIMARY KEY(a,b)` | 复合主键 | 用于表达多对多 |
| `REFERENCES` | 外键 | 保证引用完整 |
| `JOIN ... ON` | 重新关联 | 第 12 章详解 |
| `information_schema.columns` | 查列 | 验证拆分结果 |

## 4. 边界条件

- 3NF 不是终点；还有 BCNF、4NF，但业务库通常到 3NF 就够。
- 报表场景常故意冗余，这叫反范式，需要明确理由。
- 拆表后写入要维护更多外键，事务更复杂。

## 5. 注意事项对照表

| 错误写法 / 操作 | 现象 | 正确写法 | 依据 |
| --- | --- | --- | --- |
| 一列存多值 | 无法索引单值 | 拆子表 | 通用实践 |
| 部分依赖 | 数据重复 | 拆表 | 通用实践 |
| 传递依赖 | 更新异常 | 查找表 | 通用实践 |
| 一律反范式 | 更新异常 | 先 3NF | 通用实践 |
| 拆表不建外键 | 引用失效 | 加 REFERENCES | 通用实践 |
| 中间表无联合主键 | 重复关系 | 加主键 | 通用实践 |
| 不查回就交付 | 无法使用 | JOIN 验证 | 实测 |
| 用业务名当主键 | 变更困难 | 代理键 | 通用实践 |
| 冗余列不同步 | 读到旧值 | 触发器或应用层 | 通用实践 |
| 范式当教条 | 过度拆表 | 看查询模式 | 实测 |
| 不做 ERD | 关系不清 | 画图再建表 | 通用实践 |
| 忽略 NULL 语义 | 约束失效 | 显式 NOT NULL | 通用实践 |
| 用 TEXT 存金额 | 精度问题 | NUMERIC | 通用实践 |
| 用数组列代替子表 | 查询困难 | 子表 | 实测 |
| 无证据地反范式 | 维护成本上升 | 先测量 | 通用实践 |
| 不命名约束 | 报错难懂 | 显式命名 | 实测 |
| 复制表结构不用 LIKE | 手工出错 | `CREATE TABLE ... (LIKE ...)` | 实测 |
| 跳过验收 | 拆分错误不自知 | 9/9 再走 | 实测 |
