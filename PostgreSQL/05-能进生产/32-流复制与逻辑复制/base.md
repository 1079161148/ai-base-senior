# 32 流复制与逻辑复制 · 完整版

## 0. 怎么用

跑 10/10，再看第 4 节理解复制槽为什么危险。

## 1. 概念

复制是「把 WAL 变化同步到别处」。物理复制整实例一致，逻辑复制按表订阅。

## 2. 机制

```text
写操作 → WAL → walsender → 从库重放（物理）
                    → 解码插件 → 逻辑变更（逻辑）
```

## 3. API 逐个拆解

| API | 作用 | 注意 |
| --- | --- | --- |
| `pg_current_wal_lsn` | 位置 | 可比较延迟 |
| `pg_stat_replication` | 从库 | 主库上查 |
| `CREATE PUBLICATION` | 发布 | 按表 |
| `pg_create_logical_replication_slot` | 建槽 | 防 WAL 回收 |
| `pg_logical_slot_peek_changes` | 预览 | 不消费 |
| `test_decoding` | 输出插件 | 内置 |

## 4. 边界条件

- 未消费的复制槽会阻止 WAL 回收，可能撑爆磁盘。
- `peek_changes` 不推进槽位置，`get_changes` 才推进。
- 逻辑复制要求表有 replica identity（通常主键）。

## 5. 注意事项对照表

| 错误写法 / 操作 | 现象 | 正确写法 | 依据 |
| --- | --- | --- | --- |
| 槽不删 | WAL 堆积 | 用完 DROP | 实测 |
| wal_level 太低 | 逻辑复制报错 | logical | 实测 |
| peek 当消费 | 重复读 | get_changes | 实测 |
| 无主键表做逻辑复制 | 更新失败 | REPLICA IDENTITY | 实测 |
| 把复制当备份 | 误删不可恢复 | 另做备份 | 第 20 章 |
| 不监控延迟 | 从库落后不知 | 查 LSN 差 | 实测 |
| 多槽共用 | 竞争 | 每个订阅独立 | 实测 |
| 高负载建槽 | 性能影响 | 低峰 | 实测 |
| 跨大版本逻辑复制 | 不兼容 | 测试 | 实测 |
| 不查 pg_stat_replication | 状态不清 | 查视图 | 实测 |
| 流复制当读写分离万能 | 延迟问题 | 评估业务 | 实测 |
| 同步复制全开 | 写延迟高 | 按需求 | 实测 |
| 不设 hot_standby | 从库不可读 | 配置 | 实测 |
| 复制用户权限过大 | 安全风险 | 最小权限 | 第 30 章 |
| 跳过验收 | 复制认知错 | 10/10 再走 | 实测 |
| 不看 WAL 量 | 磁盘爆 | 监控 | 实测 |
| 把槽当临时表 | 概念混 | 它是流式状态 | 实测 |
| 不做故障切换演练 | 真出事慌 | 定期演练 | 实测 |

## 6. 最佳实践

每个逻辑槽必须有明确消费者和清理策略；监控 WAL 积压与从库延迟。
