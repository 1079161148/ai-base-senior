# 28 存储过程与触发器 · 完整版

## 0. 怎么用

跑 10/10，再看第 4 节理解触发器的隐式执行。

## 1. 概念

函数显式调用，触发器隐式执行。两者都能把逻辑放到数据库层。

## 2. 机制

```text
INSERT/UPDATE → BEFORE 触发器 → 写行 → AFTER 触发器 → 返回
```

## 3. API 逐个拆解

| API | 作用 | 注意 |
| --- | --- | --- |
| `LANGUAGE sql` | 简单函数 | 可内联 |
| `LANGUAGE plpgsql` | 过程式 | 支持变量和条件 |
| `IMMUTABLE/STABLE/VOLATILE` | 易变性标记 | 影响优化 |
| `NEW`/`OLD` | 行变量 | INSERT 无 OLD |
| `FOR EACH ROW` | 行级触发 | 还有语句级 |

## 4. 边界条件

- BEFORE 触发器必须返回 NEW 才会写入。
- `OLD.price != NEW.price` 遇 NULL 会返回 NULL，用 `IS DISTINCT FROM`。
- 触发器里再修改同一张表可能递归。

## 5. 注意事项对照表

| 错误写法 / 操作 | 现象 | 正确写法 | 依据 |
| --- | --- | --- | --- |
| BEFORE 不 RETURN NEW | 插入 NULL 行 | 显式返回 | 实测 |
| `!=` 比较 NULL | 不触发 | IS DISTINCT FROM | 实测 |
| 触发器递归 | 无限循环 | 条件判断 | 实测 |
| 触发器过多 | 写变慢 | 控制数量 | 实测 |
| 函数标记错 IMMUTABLE | 优化错误 | 按实际标记 | 实测 |
| 不查 pg_trigger | 结构不清 | 查元数据 | 实测 |
| 删表不删函数 | 残留对象 | 显式 DROP | 实测 |
| AFTER 里改 NEW | 无效 | 用 BEFORE | 实测 |
| 审计表无索引 | 查询慢 | 建索引 | 第 22 章 |
| 语句级触发器当行级 | 只触发一次 | 声明 FOR EACH ROW | 实测 |
| 不测无变化更新 | 审计冗余 | 加条件 | 实测 |
| 函数无默认值 | 调用繁琐 | 加 DEFAULT | 实测 |
| 不走 schema 隔离 | 命名冲突 | chNN | 实测 |
| 不设 SECURITY DEFINER | 权限问题 | 按需设置 | 第 30 章 |
| 大批量导入触发器 | 慢 | 临时禁用 | 实测 |
| 跳过验收 | 触发器未验证 | 10/10 再走 | 实测 |
| 把函数当事务 | 语义混 | 事务在外层 | 第 16 章 |
| 不记录触发器用途 | 维护困难 | COMMENT | 实测 |

## 6. 最佳实践

审计字段用触发器兜底，复杂业务仍放应用层；触发器逻辑保持短小。
