# 34 完整建模评审 · 完整版

## 0. 怎么用

## 1. 概念

建模评审不是凭感觉，而是用元数据查询逐项核对数据库目录（`information_schema`、`pg_catalog`）。能查出来的约束才算落地，写在文档里的约定不算。

## 2. 机制

```text
业务需求 → 识别实体 → 定主键 → 定关系（外键）→ 定类型 → 加约束 → 加索引 → 评审清单核验
```

## 3. 逐项拆解

| 维度 | 核验查询 | 达标信号 |
| --- | --- | --- |
| 主键 | `information_schema.table_constraints` | `PRIMARY KEY` |
| 外键 | 同上 + `constraint_column_usage` | `FOREIGN KEY` |
| 类型 | `information_schema.columns.data_type` | `numeric` / `timestamp with time zone` |
| 必填 | `is_nullable='NO'` | 核心字段非空 |
| 取值 | `constraint_type='CHECK'` | 非法值被拦 |
| 唯一 | `constraint_type='UNIQUE'` | 业务键唯一 |
| 级联 | `pg_constraint.confdeltype` | `c` / `n` / `r` |

## 4. 边界条件

- `UNIQUE` 在 PostgreSQL 允许多个 NULL，需要 `NOT NULL` 配合才是真正唯一。
- 外键不自动建索引，高频按外键查询时要手动补索引。
- CHECK 不校验子查询，跨表规则要靠触发器或应用层。
- `ON DELETE CASCADE` 会静默删子记录，删前要确认业务允许。

## 5. 注意事项对照表

| 错误写法 / 操作 | 现象 | 正确写法 | 依据 |
| --- | --- | --- | --- |
| 金额 FLOAT | 精度丢失 | NUMERIC | 第 04 章 |
| 时间 TEXT | 排序错误 | TIMESTAMPTZ | 第 04 章 |

| 逗号分隔多值 | 违反 1NF | 拆表 | 第 07 章 |
| 无外键 | 脏数据 | REFERENCES | 第 06 章 |
| 隐式级联 | 误删子记录 | 显式 ON DELETE | 第 06 章 |
| 无 CHECK | 负数入库 | CHECK | 第 04 章 |
| 业务键不唯一 | 重复数据 | UNIQUE | 第 04 章 |
| 外键无索引 | JOIN 变慢 | 补索引 | 第 22 章 |
| 全 TEXT | 无法校验 | 结构化类型 | 第 04 章 |
| 命名混乱 | 维护困难 | 统一规范 | 一致性原则 |

## 6. 最佳实践
