# 30 权限系统与行级安全 · 完整版

## 0. 怎么用

跑 10/10，再看第 4 节理解为什么 superuser 测不出 RLS。

## 1. 概念

权限决定「能不能访问对象」，RLS 决定「能看到哪些行」。

## 2. 机制

```text
连接角色 → schema USAGE → 表/列权限 → RLS 策略 → 可见行
```

## 3. API 逐个拆解

| API | 作用 | 注意 |
| --- | --- | --- |
| `CREATE ROLE` | 角色 | LOGIN 才能连接 |
| `GRANT` | 授权 | 列级可细化 |
| `has_*_privilege` | 检查 | 返回 bool |
| `ENABLE RLS` | 启用 | 默认拒绝 |
| `CREATE POLICY` | 策略 | USING 控制读 |
| `SET LOCAL ROLE` | 切换 | 事务级 |

## 4. 边界条件

- 超级用户和 `BYPASSRLS` 角色不受 RLS 限制。
- 只 GRANT 表权限而不 GRANT schema USAGE 仍然访问失败。
- RLS 开启但无策略时，普通角色看不到任何行。

## 5. 注意事项对照表

| 错误写法 / 操作 | 现象 | 正确写法 | 依据 |
| --- | --- | --- | --- |
| 用 admin 测 RLS | 全可见 | 普通角色 | 实测 |
| 漏 GRANT USAGE | 访问失败 | 补授 schema | 实测 |
| RLS 无策略 | 零行 | 建策略 | 实测 |
| 不清理角色 | 残留对象 | DROP OWNED | 实测 |
| 列级权限当表级 | 误判 | has_column_privilege | 实测 |
| 密码写进脚本 | 泄露 | 用环境变量 | 实测 |
| 策略用 current_user | 映射复杂 | 用自定义 GUC | 实测 |
| 不测 REVOKE | 权限残留 | 补用例 | 实测 |
| FORCE RLS 误用 | 表主也受限 | 按需 | 实测 |
| 策略过宽 | 数据泄露 | 加 tenant 条件 | 实测 |
| 不查 pg_policy | 结构不清 | 查元数据 | 实测 |
| 视图绕过 RLS | 安全风险 | 理解权限链 | 实测 |
| 角色嵌套复杂 | 难维护 | 简化角色树 | 实测 |
| 不设密码有效期 | 安全隐患 | 定期轮换 | 实测 |
| 跳过验收 | 隔离失效 | 10/10 再走 | 实测 |
| 把 RLS 当应用过滤 | 语义不同 | 它是兜底 | 实测 |
| 不开 RLS 只靠应用 | 越权风险 | 双层防护 | 实测 |
| 策略函数标 VOLATILE | 性能差 | 尽量 STABLE | 实测 |

## 6. 最佳实践

多租户先 RLS 兜底，再做应用层过滤；用非超级用户跑验收。
