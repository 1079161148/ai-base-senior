# 12 JOIN 四种连接 · 完整版

## 0. 怎么用

跑 12/12，再看第 4 节理解 ON 与 WHERE 的差别。

## 1. 概念

JOIN 把分散在多张表的信息按条件拼回来。

## 2. 机制

```text
INNER:  A ∩ B
LEFT:   A 全部 + B 匹配部分（其余 NULL）
RIGHT:  B 全部 + A 匹配部分
FULL:   A ∪ B
```

## 3. API 逐个拆解

| API | 作用 | 注意 |
| --- | --- | --- |
| `ON` | 连接条件 | LEFT 中放这里不会过滤左表 |
| `USING` | 同名列简写 | 结果里该列只出现一次 |
| `CROSS JOIN` | 笛卡尔积 | 行数相乘 |
| 表别名 | 区分表 | `FROM users u` |
| 自 JOIN | 表连自己 | 必须别名 |

## 4. 边界条件

- `LEFT JOIN` 的 `WHERE 右表列=值` 会把 NULL 行过滤掉，逻辑上退化为 INNER。
- `FULL JOIN` 两边都可能补 NULL。
- `USING` 要求两边列名完全相同。

## 5. 注意事项对照表

| 错误写法 / 操作 | 现象 | 正确写法 | 依据 |
| --- | --- | --- | --- |
| LEFT 后 WHERE 右表 | 退化 INNER | 条件放 ON | 实测 |
| 无 ON 条件 | 笛卡尔积 | 显式 ON | 实测 |
| 多表无别名 | 列歧义 | 起别名 | 实测 |
| USING 不同名列 | 报错 | 用 ON | 实测 |
| 自 JOIN 无别名 | 报错 | 两个别名 | 实测 |
| 以为 RIGHT 可替代 LEFT | 可读性差 | 统一用 LEFT | 实测 |
| JOIN 大表无索引 | 慢 | 给连接键建索引 | 通用实践 |
| 重复连接键导致行数膨胀 | 结果变多 | 检查唯一性 | 实测 |
| 用隐式逗号连接 | 难维护 | 显式 JOIN | 实测 |
| 不测 NULL 分支 | 漏数据 | 查 IS NULL | 实测 |
| CROSS JOIN 无限制 | 结果爆炸 | 加 WHERE | 实测 |
| FULL JOIN 列选择错 | 多列 NULL | COALESCE | 实测 |
| JOIN 后聚合漏组 | 计数错 | GROUP BY 主键 | 实测 |
| 别名用保留字 | 报错 | 换名 | 实测 |
| 不写排序 | 顺序不稳 | ORDER BY | 第 10 章 |
| 连接条件用函数 | 索引失效 | 预处理字段 | 通用实践 |
| 跳过验收 | 行数错不自知 | 12/12 再走 | 实测 |
| 把 ON 当 WHERE | 语义混 | 分清位置 | 实测 |

## 6. 最佳实践

连接条件放 ON，结果集过滤放 WHERE；统一用 LEFT JOIN 保持可读性。
