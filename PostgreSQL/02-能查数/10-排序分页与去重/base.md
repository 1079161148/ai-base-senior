# 10 排序分页与去重 · 完整版

## 0. 怎么用

跑 10/10，再看第 4 节理解分页稳定性。

## 1. 概念

结果集默认是无序的。要稳定顺序必须显式排序。

## 2. 机制

```text
FROM → WHERE → SELECT → DISTINCT → ORDER BY → LIMIT/OFFSET
```

DISTINCT 在 ORDER BY 之前执行，所以排序依据的列必须出现在 SELECT 里。

## 3. API 逐个拆解

| API | 作用 | 注意 |
| --- | --- | --- |
| `ASC`/`DESC` | 方向 | 默认 ASC |
| `NULLS FIRST/LAST` | 空值位置 | 升序默认 LAST |
| `LIMIT` | 取几条 | 后面可加 OFFSET |
| `DISTINCT` | 整行去重 | 多列组合判重 |
| `DISTINCT ON` | 分组取首 | 必须 ORDER BY 同组键开头 |

## 4. 边界条件

- `OFFSET` 大时数据库仍需扫描前面所有行，深分页慢。
- `DISTINCT ON` 的 ORDER BY 必须以分组列开头，否则结果不确定。
- `LIMIT 0` 返回空集但仍执行计划。

## 5. 注意事项对照表

| 错误写法 / 操作 | 现象 | 正确写法 | 依据 |
| --- | --- | --- | --- |
| 分页不排序 | 重复/漏行 | 加 ORDER BY | 实测 |
| DISTINCT 后排未选列 | 报错 | 放入 SELECT | 实测 |
| DISTINCT ON 无 ORDER BY | 结果随机 | 必须配 | 实测 |
| OFFSET 深分页 | 慢 | 游标分页 | 通用实践 |
| 以为 NULL 排最后 | 方向不同规则不同 | 显式 NULLS | 实测 |
| LIMIT 2,3 | 非标准 | LIMIT 3 OFFSET 2 | 实测 |
| 多列排序方向混用 | 语义不清 | 每列写 ASC/DESC | 实测 |
| ORDER BY 别名在 WHERE | 不可用 | 重复表达式 | 实测 |
| 用 row_number 代替 DISTINCT ON | 可行但冗长 | 简单场景用前者 | 实测 |
| 不去重直接统计 | 重复计数 | DISTINCT | 通用实践 |
| 排序大文本列 | 慢 | 排序键索引 | 通用实践 |
| DISTINCT 全列 | 等于没去重 | 选必要列 | 实测 |
| 分页参数无上限 | 一次拉全表 | 限制 size | 实测 |
| 把 LIMIT 当过滤 | 语义错 | 用 WHERE | 实测 |
| 不测第二页 | 漏行难发现 | 多页断言 | 实测 |
| NULLS FIRST 配 DESC | 顺序反直觉 | 显式测试 | 实测 |
| 不用确定性排序键 | 并列行顺序乱 | 加主键兜底 | 实测 |
| 跳过验收 | 分页错不自知 | 10/10 再走 | 实测 |

## 6. 最佳实践

所有分页都加「业务排序键 + 主键」作为确定性顺序。
