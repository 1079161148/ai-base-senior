# 13 子查询与 CTE · 完整版

## 0. 怎么用

跑 11/11，再看第 4 节理解 EXISTS 与 IN 的差别。

## 1. 概念

子查询是嵌在另一个 SQL 里的查询；CTE 是给它起名字。

## 2. 机制

```text
标量子查询 → 返回单值，可用于 WHERE 比较
EXISTS     → 短路判断，找到一行就停
CTE        → 优化器可内联或物化
递归 CTE   → anchor + recursive 两步
```

## 3. API 逐个拆解

| API | 作用 | 注意 |
| --- | --- | --- |
| `IN` | 集合判断 | 列表含 NULL 危险 |
| `EXISTS` | 存在判断 | 常用 `SELECT 1` |
| `WITH` | 命名子查询 | PG12+ 可内联 |
| `RECURSIVE` | 递归 | 必须 UNION ALL |
| `MATERIALIZED` | 强制物化 | 多次引用时用 |

## 4. 边界条件

- `NOT IN` 集合里有一个 NULL，整个表达式就是 UNKNOWN。
- 标子查询返回多行会报错。
- 递归 CTE 的深度由数据决定，需防环。

## 5. 注意事项对照表

| 错误写法 / 操作 | 现象 | 正确写法 | 依据 |
| --- | --- | --- | --- |
| NOT IN 含 NULL | 零行 | NOT EXISTS | 实测 |
| 标量子查询多行 | 报错 | 加聚合/LIMIT | 实测 |
| 递归无 anchor | 报错 | 先写终止分支 | 实测 |
| 递归成环 | 死循环 | 加深度限制 | 实测 |
| CTE 当缓存 | 不一定物化 | 显式 MATERIALIZED | 实测 |
| EXISTS 里 SELECT * | 无意义 | SELECT 1 | 实测 |
| IN 列表过长 | SQL 大 | 改 JOIN | 实测 |
| 相关子查询无索引 | 慢 | 给关联列建索引 | 通用实践 |
| CTE 里 ORDER BY | 可能被消除 | 外层排序 | 实测 |
| 多次引用 CTE | 可能重复计算 | MATERIALIZED | 实测 |
| 子查询别名漏写 | FROM 报错 | 起别名 | 实测 |
| 用 = ANY 代替 IN | 可行但少用 | IN 更清晰 | 实测 |
| 不测 NULL 分支 | 隐患 | 补用例 | 实测 |
| 树查询不用递归 CTE | 多次查询 | 一条 SQL | 实测 |
| 递归深度无上限 | 栈风险 | 加 depth 条件 | 实测 |
| 把 CTE 当视图 | 生命周期不同 | 分清作用域 | 实测 |
| 不跑 EXPLAIN | 不知是否物化 | 第 21 章 | 通用实践 |
| 跳过验收 | NULL 陷阱漏掉 | 11/11 再走 | 实测 |

## 6. 最佳实践

「不存在」一律用 `NOT EXISTS`，不用 `NOT IN`。
