# 15 电商 33 题实战 · 完整版

## 0. 怎么用

先跑 33/33，再把错题单独抄出来重写一遍。

## 1. 概念

综合题的价值不在记住答案，而在学会「看到需求 → 选 WHERE 还是 HAVING → 选 JOIN 还是子查询」。

## 2. 机制

```text
业务问题 → 选表 → 定连接 → 定过滤位置 → 定聚合粒度 → 排序分页
```

## 3. API 逐个拆解

| API | 在本章的题号 |
| --- | --- |
| `WHERE` | 01–11 |
| `GROUP BY`/`HAVING` | 14–20、24、26 |
| `JOIN` | 03、19–22、27 |
| `NOT EXISTS` | 25 |
| `date_trunc` | 30–31 |
| `LIKE` | 32 |
| `LIMIT/OFFSET` | 10、11、23、29、33 |

## 4. 边界条件

- 简化数据集只有 5 个用户、7 张订单，部分题目结果为空属于正常。
- `date_trunc('month', ts)` 返回月初时间戳。
- `HAVING sum(...) > 10000` 依赖金额字段非空。

## 5. 注意事项对照表

| 错误写法 / 操作 | 现象 | 正确写法 | 依据 |
| --- | --- | --- | --- |
| NOT IN 含 NULL | 零行 | NOT EXISTS | 第 13 章 |
| 分组条件写 WHERE | 报错 | HAVING | 第 11 章 |
| JOIN 忘 ON | 笛卡尔积 | 显式 ON | 第 12 章 |
| Top-N 无 ORDER BY | 随机 | 显式排序 | 第 10 章 |
| 日期字符串格式错 | 解析失败 | ISO 格式 | 实测 |
| 不测空结果题 | 误以为错 | 检查数据 | 实测 |
| COUNT(DISTINCT) 漏 DISTINCT | 计数偏大 | 加上 | 第 11 章 |
| 用 INNER 代替 LEFT 找孤儿 | 零行 | LEFT + IS NULL | 第 12 章 |
| 聚合列不在 GROUP BY | 报错 | 补列 | 第 11 章 |
| 分页无排序 | 重复漏行 | ORDER BY | 第 10 章 |
| 子查询别名漏写 | 报错 | 起别名 | 第 13 章 |
| 标量比较返回多行 | 报错 | IN 或聚合 | 第 13 章 |
| 不写列名 INSERT | 顺序敏感 | 显式列名 | 第 08 章 |
| 金额用 REAL | 精度误差 | NUMERIC | 第 04 章 |
| 不看执行计划 | 慢不知原因 | 第 21 章 | 原仓库 06 |
| 把题当答案背 | 换数据就不会 | 理解模式 | 实测 |
| 跳过验收 | 错题不自知 | 33/33 再走 | 实测 |
| 不小题库直接学 | 缺手感 | 逐题写 | 原仓库 04 |
